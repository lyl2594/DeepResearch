# 【DeepResearch智能研究平台】企业级AI研究系统开发项目 — 详细版

## 项目概述

DeepResearch是一套基于LangGraph构建的企业级智能研究平台，实现从用户提问到研究报告生成的全流程自动化。平台核心能力包括：SSE流式对话、多步骤研究计划、HITL人机协作审核、节点级耗时观测、MCP动态工具扩展、RAG私有知识库检索。项目周期5个月，完成从需求分析到生产级部署的全生命周期开发。

### 实现思路是什么？

**状态机模式**：采用LangGraph的StateGraph构建有向无环图，每个节点是状态机的一个状态，条件路由决定状态转移。

**Command模式**：节点通过`Command(update={...}, goto="node_name")`返回状态更新和下一跳，实现声明式流程控制。

**HITL设计**：在关键决策点（计划审核、检索审核、报告审核）插入`interrupt()`暂停流程，等待用户反馈后继续执行。

**评估驱动**：步骤评估和终评作为流程控制的核心驱动力，低分自动触发重试或重规划。

### 技术亮点

- **goto机制**：通过`Command(goto="node_name")`实现灵活的流程跳转，支持复杂的条件分支和循环
- **Checkpointer**：集成`AsyncPostgresSaver`实现状态持久化，支持对话中断后恢复
- **skip机制**：支持用户跳过当前步骤重试，恢复最近一次完整结果，不产生重复执行
- **structured_output**：planner使用`PlanMinimal`结构输出，eval使用`EvaluationResponse`结构输出，保证JSON格式可靠

### 实操流程

```
1. 用户提问 → coordinator分流意图
2. 研究需求 → planner生成多步骤计划
3. human_feedback审核计划 → 用户确认后继续
4. research_team调度 → 按步骤类型路由到researcher/coder
5. researcher执行 → 调用工具完成研究步骤
6. eval评估步骤质量 → 低分触发重试，高分继续
7. 所有步骤完成 → reporter生成报告
8. report_review审核报告 → 用户确认后进入终评
9. final_report_evaluator终评 → 低分触发reflection loop
10. 终评通过 → 输出最终报告
```

**1. @timed_node装饰器**

```python
def timed_node(func: Callable) -> Callable:
    @functools.wraps(func)
    async def _async_wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return await func(*args, **kwargs)
        finally:
            logger.info(f"[timing] {func.__name__}: {time.perf_counter() - start:.2f}s")
    
    @functools.wraps(func)
    def _sync_wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            logger.info(f"[timing] {func.__name__}: {time.perf_counter() - start:.2f}s")
    
    return _async_wrapper if asyncio.iscoroutinefunction(func) else _sync_wrapper
```

### 实现思路是什么？

**横切关注点分离**：通过装饰器模式在不修改业务代码的情况下增加耗时统计能力，实现AOP（面向切面编程）。

**数据库健壮性**：利用PostgreSQL原生能力（MVCC+连接池），设置双重超时防止单点故障。

- **落库分离**：业务落库和checkpoint落库分离，职责清晰
- **Markdown解析**：报告导出时解析Markdown，支持标题、粗体、列表等格式

### 实操流程

```
1. 启动FastAPI服务：uvicorn server.app:app --reload
2. 前端建立SSE连接：POST /api/chat/stream
3. 后端组装workflow_input和workflow_config
4. 调用graph.astream执行LangGraph
5. 按事件类型转换为SSE帧并推送到前端
6. 同时落库到ChatStream和LanggraphEvent表
7. 前端接收事件并渲染UI
8. 报告完成后调用POST /api/graph/report导出Word文档
```

### 关键设计理念

1. **声明式流程**：通过LangGraph的Command模式实现声明式流程控制，代码可读性高
2. **横切能力叠加**：计时、安全门、工具注入作为横切能力叠加，不破坏业务代码
3. **优雅降级**：辅助功能失败返回空列表，不影响主流程
4. **安全优先**：MCP默认关闭，配置白名单过滤
5. **开闭原则**：Retriever抽象允许扩展新provider，无需修改调用方代码
6. **可验证性**：每个功能有明确的验收证据和场景验证矩阵
